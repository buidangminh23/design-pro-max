# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- Temporary test repositories disable automatic Git maintenance, and teardown retries transient filesystem errors before failing, preventing release-pack checks from failing while their temporary object directories are being removed.

### Added

- Two bundled skills next to `apple`: `design-spacing-rhythm` from buidangminh23/spacing-skill v2.16.2 (8 files) and `icons-pro-max` from buidangminh23/icons-pro-max v2.3.0 (801 files, 799 of them brand logos), copied byte for byte from the commit of each release tag with the repository's licence as `LICENSE`. `vendor/bundles.json` pins each one by repository, tag and commit and records every file's size and hash. `scripts/bundle-sync.mjs` has `sync` (proves the tag still points at the pinned commit, refuses symlinks, submodules, unsafe names, git metadata, `metadata.json`, a second visible `SKILL.md` and media outside the allowed folder), an offline `check`, and `update`, which moves a bundle to its repository's latest release. `BUNDLED_MEDIA` in `scripts/lib/bundles.mjs` lets only `icons-pro-max` ship `.svg` and `.png` files, only under its `assets/` folder; the history check and the release check accept each one only with the bytes `vendor/bundles.json` records at the same commit, and the release check also requires every bundled file and licence in the ZIP with its recorded hash and nothing else. CI and the release workflow run `bundle-sync.mjs check`; `gen.mjs` writes the README table of bundled skills. Tests cover the manifest validator, the media rule, tampered bundles, sync from a fake upstream (moved tags, a wrong skill name) and the history and release checks; each new check was seen to fail with its code taken out.
- `.github/workflows/bundle-sync.yml`: every day at 03:17 UTC and by hand, moves each bundled skill to the latest release of its repository, regenerates and checks everything, pushes the `bundle-sync` branch, opens one pull request, starts CI on it and merges it once CI passes and `main` has not moved.
- README badges for GitHub views over 14 days and the licence. `scripts/badges.mjs` renders the view badge from the GitHub traffic API, and the Badges workflow (`.github/workflows/badges.yml`) refreshes it on the `badges` branch every six hours. The npm badges wait for the public package from 0.2.0; the script never asks npm about the private name.
- `scripts/ci-local.mjs` (`npm run ci:local`): runs every step of CI's test job, read from `ci.yml`, and `scripts/verify.mjs` when its tools are installed, then lists what the local run did not cover.
- `scripts/release.mjs stats`, `bump X.Y.Z` and `push-tag vX.Y.Z`. `stats` computes the card stats from committed files (guides, active guides, sourced error rules, must-fail fixtures, eval cases, dated ledger claims), and `check` fails when `web-card.json` shows other values. `bump` writes the version into `package.json` and the plugin manifests and the stats into the card. `push-tag` tags HEAD only when it is `origin/main` with a clean tree and ready inputs, pushes the tag by name with three attempts, and succeeds only when `git ls-remote` lists it at HEAD.
- `scripts/lint-ip.mjs` (`npm run lint:ip`, also run by `npm test`): six checks over the project's own files. `identifiers` fails class names, custom properties, module ids and media file names from the private research; `apple-text` fails an 8-word run that matches the hashed Apple corpus outside quotes of at most 20 words; `phrases` fails imitation and endorsement wording in English and Vietnamese in the README, `package.json`, the plugin manifests, the card and the router description; `substitution` fails host substitution syntax in the router, `NOTICE.md` and every `PART.md`; `privacy` fails private machine names, paths and repository names; `versions` fails an OS or SDK version past the newest release. Identifiers, private terms and the corpus are committed only as salted SHA-256 hashes in `evidence/ip-hashes.json`; `--build` rebuilds them from a private terms file. Each check was seen to fail on a planted violation in a real file. `NOTICE.md` states the Apple-text allowances and that Apple's documentation, the Swift book, swift.org, Swift Evolution and Apple's MIT samples are not in the corpus yet.
- `designs/apple.json`: the apple skill's design record: the Apple marks, the referential phrase, the trademark-policy and site-terms URLs, the measuring method, the never-ship list, the Apple-text allowances, the phrase gates, the newest released OS (27.0) and the owner's sign-off on the skill name and icon.
- The first own part, `skills/apple/launch-scroll/`: a `PART.md` guide for pinned and scroll-scrubbed scenes on web pages (when not to pin, the JavaScript and CSS engines, geometry, gates for reduced motion, short viewports and blocked autoplay, scrub video, frame sequences, report with a proof boundary), four references, a generated `references/evidence.md`, a scene library (`scene-progress.js`, `seek-queue.js`, `scrub-loader.js` and `scene.css`), three reference pages, `scripts/probe-scene.mjs`, which checks a served page in headless Chromium at several viewports, and `scripts/encode-scrub.mjs`, which encodes a scrub film with closed GOPs, colour tags and a matching start frame and checks its own output. The router routes scroll-pinned web scenes to it.
- `skills/apple/shared/`: the checker runtime the own parts share. One JSON line per finding and a summary with the proof boundary; exit 0, 1, 2 for a missing argument or tool, 3 for a sandbox; Playwright loaded from the user's project with `--project`; an MP4 box reader that tells IDR from open-GOP keyframes; `check-media.mjs` for scrub encodes; a local test server with and without range requests; and the motion classes table.
- `rules.json`: 8 error rules and 9 warnings for launch-scroll, each with its evidence, check, fixtures and the checker that implements it. `evidence/ledger.json`: 31 own-words claims with a label, a source and the SHA-256 of the private finding they were written from; `scripts/import-findings.mjs --check` recomputes those hashes against the research folder, which never enters the repository.
- `fixtures/launch-scroll/`: a pass and a fail case for every error rule, 12 cases in all, with pages; the media is built at run time from a generated source. `scripts/verify.mjs` runs every case through the checkers from a copy outside the repository and judges it red first: a fail case must exit 1 with an error for its rule, a pass case must pass its rule without skipping it. `.github/workflows/verify.yml` runs it on Ubuntu with ffmpeg and headless Chromium for changes to the own parts and on every tag.
- Tests for the ledger and rules schemas, the citation lint (every cited id exists, every number with a unit is cited and appears in the cited values), the size and contents caps of each `PART.md`, the fixtures, the harness, the MP4 reader, the test server, the scene library's pure functions and the checkers' exit codes outside the repository; `test/token-budget.json` records the measured characters per token.
- `CONTRIBUTING.md`: an issue first, MIT-only sources, how a part is added and the rules for the project's own files.
- README Install section: install only into a host's own skill roots, never run `npx skills` with `--full-depth`, keep the skill out of Codex executor-environment roots (they include hidden folders, so every part would register), use one install channel per machine, and invoke `/apple` or `$apple` directly when a large library hides its description.
- The router's non-affiliation line, under its title: independent project, not affiliated with Apple Inc., see `NOTICE.md`.
- Workflows. `ci.yml` runs the tests and every check, including the history check and a release pack, on Ubuntu, macOS and Windows with Node 22 and 24. `release.yml` runs on `vX.Y.Z` tags, one run at a time, for tags on `main`: it repeats every check, packs the ZIP, creates a draft release holding exactly the ZIP and `SHA256SUMS.txt`, downloads and verifies the assets, then publishes the release as Latest, never as a prerelease and never behind a newer published version; a tag that is already published is only verified. `vendor-sync.yml` runs on Mondays at 02:41 UTC and by hand: a read-only job stages and guards upstream changes; a second job confirms them against upstream, classifies, applies and checks them, pushes the `vendor-sync` branch, opens or updates one same-repository pull request, starts the CI workflow on it, merges it only when it is `safe` and that CI run passed on its head commit, and labels it `needs-review` otherwise; after 45 quiet days it enables itself through the API and opens an issue, without pushing to `main`. Every action is pinned to a commit, each job states its permissions, no checkout keeps credentials, a push authenticates only its own step, and no expression is interpolated into a shell script; tests check all of these.
- `scripts/vendor-sync.mjs stage`, `classify`, `confirm` and `apply` for upstream updates. `stage` reads every source's upstream HEAD, stops when all are at their pins, and otherwise copies the parts of each moved source at its new HEAD, after a blobless clone proves the pin is an ancestor; a rewritten history or a part that no longer syncs blocks only that source. `classify` calls an update `safe` only when no file that ships in a moved part changes; any added, removed or edited file, executable bit, licence or skill name makes it `needs-review`, with one reason per change and the added lines of each changed file scanned for links by host and path, commands, injection phrases across line breaks, words that mix scripts and fenced code, plus a pull request body. `confirm` re-fetches each moved source at its staged commit, proves that commit descends from the pin on the default branch, and compares every moved part with a fresh copy. `apply` refuses links, special files, paths outside the moved parts and manifest changes other than commits.
- `scripts/release.mjs`: `check` validates the release inputs: the payload, `skills.json`, the export-ignore lines, that every top-level item is payload or repo-only, and a private `design-pro-max` package before 0.2.0 or a public `@<scope>/design-pro-max` one from then on; with a tag also the version, its dated CHANGELOG entry and a README without the pre-release banner. `notes` prints that entry; `pack` builds `design-pro-max-vX.Y.Z.zip` from HEAD with git archive under `TZ=UTC` plus `SHA256SUMS.txt`; `verify` reads the ZIP itself and checks the installers' contract: one visible `SKILL.md` per skill in `skills.json`, every vendored file equal to its `UPSTREAM.json` hash, one MIT licence per part, exactly the manifest's parts, no entry name over 150 characters, and no symlinks, `__pycache__`, compiled Python, `metadata.json` or unreviewed media; with a checkout it also compares the ZIP with the tracked files of the tag, or of HEAD, byte for byte. `.gitattributes` marks the repo-only paths `export-ignore`, including `.claude-plugin`, `.codex-plugin` and `web-card.json`, never anything under `skills/`. Replayed through three install routines (unzip and `cp -R`, Python `zipfile` and `copytree`, PowerShell `Expand-Archive` and `Copy-Item`), the ZIP installs every file of `.vendor` and all 38 parts with their contents intact; unzip and `Expand-Archive` keep the executable bits and Python's `zipfile` drops them, which changes nothing because the parts call their scripts through `python3`.
- `scripts/check-history.mjs`: fails when any commit reachable from HEAD adds an image, font, media file or archive, found by extension or by its first bytes, other than a reviewed file with its reviewed bytes (today only the apple skill's icon), or any file in a vendored part's `assets/` or `agents/` folder; merges are checked against each parent and a shallow clone fails.
- `scripts/gen.mjs`: writes `skills.json` (the skills an installer finds), `skills/apple/references/parts-index.md` (every part with its group, status, activation check, prerequisites and errata pointers, linked from the router), the README credits table, the trademark line in the README and in `NOTICE.md`, and the licence of each third-party drawing the skill ships in `NOTICE.md`; `--check` fails when one is out of date. The trademark line is built from the Apple marks the project's own text uses, so it now also credits iOS and macOS and carries Cisco's IOS sentence.
- The apple skill's icon: the Apple logo at `skills/apple/assets/apple.svg`, copied unmodified from icons-pro-max (devicon drawing, MIT; the logo is Apple's trademark and outside this project's MIT license), a Codex `agents/openai.yaml` with the display name and icon, and `skills/apple/NOTICE.md` with the disclaimer, the icon's source and devicon's full licence text, which `THIRD_PARTY_NOTICES.md` carries too.
- Repository scaffold: MIT licence, a package manifest for Node 22 or later with no dependencies, and git attributes that keep vendored bytes unchanged.
- `vendor/sources.json`: 38 parts from 9 repositories, pinned to full commits, with excludes, activation checks, prerequisites, risks, errata and the Apple text each part is known to quote (`appleText`).
- `scripts/vendor-sync.mjs`: `sync` fetches each pinned repository once and copies every part byte for byte with its licence and an `UPSTREAM.json` record; `check` verifies the tree offline; `notices` regenerates `THIRD_PARTY_NOTICES.md`. Sync refuses to run while the vendor folder holds a symlink or special file, never writes outside it, and refuses upstream files that would change what git stores or collide with the files it writes.
- `UPSTREAM.json` for every part: identity, licence, activation, prerequisites, risks, errata and `appleText` first, then each file's SHA-256, size and executable bit. The per-file hashes cover every script, so no separate script hashes are kept; hosts and risky-command counts are computed by the guard on each run instead of being stored.
- `scripts/vendor-guard.mjs`: an offline guard over what git would ship, for licences, part files, sizes, file system entries, file types and signatures, UTF-8, names, hidden Unicode, secrets, skill layout and personal data, with risky command patterns reported as warnings.
- 38 MIT-licensed parts under `skills/apple/.vendor/`, unmodified at their pinned commits: 6 active and 32 inactive until an Xcode project, a Tuist project, or a paid Apple Developer Program account with the asc CLI exists. Agent UI metadata and icon images are excluded, so no vendored image ships; the skill's own icon is the only image in a release. `THIRD_PARTY_NOTICES.md` credits every source with its licence text and says that quoted Apple text is not covered by those licences.
- The `apple` skill: a router `SKILL.md` with standing rules (full reads, part paths resolved from the file that mentions them, activation checks, an approval gate for App Store Connect mutations and disk cleanup deletions, asc telemetry off), a routing table and a parts index.
- README with the layout, why `.vendor` is hidden, the parts and their prerequisites, credits, maintenance commands, exclude glob rules and disclaimers.
- Tests for the manifest, the vendored tree and notices, every guard rule on its own fixture, both command-line tools (including runs through a symlinked path and FIFOs where files are expected), sync against local fake upstream repositories, the router and its path rule, and the README.

### Changed

- The router's description covers pinned and scroll-scrubbed web scenes and its second sentence opens with "Use when"; two standing rules cover own parts (read `PART.md` in full, run scripts by absolute path with `--project`, report the proof boundary) and App Store screenshots (framed screenshots only for the user's own listing, no Apple logos or store badges from an icon library). The full parts index moved to `references/parts-index.md`, which `gen.mjs` now also gives an own-parts section; the router keeps a pointer and a summary.
- The router's description, after the first routing eval run: its "Use when" list now opens with App Store Connect and TestFlight through the asc CLI and names signing, notarizing, ad hoc installs, What's New and promotional text, ASO and Apple Ads; its not-for clause now names launch and preview videos, store screenshots and GSAP APIs. It stays at 499 characters, so "Routes each task to one bundled guide" was dropped.
- `gen.mjs` writes each own part's `references/evidence.md` from the ledger and the rules, and the trademark line now credits Safari.
- The router's description opens with a referential phrase, "For Apple app code (SwiftUI, Swift 6, SwiftData, Xcode, App Store).", instead of starting with the mark; the first sentence stays within 68 characters and keeps its keywords.
- The router runs Python part scripts as `python3 -B` with an absolute path, or with `PYTHONDONTWRITEBYTECODE=1`, so no `__pycache__` lands in the installed skill; its SwiftData row says "the Query macro" and its SwiftUI row "SDK 26 and 27 deprecations".
- `.gitignore` anchors `node_modules`, `dist` and `.cache` at the root, so a vendored part may ship folders with those names.
- The guard fails git metadata files anywhere under `skills/`, not only inside vendored parts.

### Fixed

- Two errata named a pre-release macOS and SDK version; they now cite Apple's documentation or a condition instead, and a test fails any OS or SDK version past the newest release in the manifest or the project's own text.
- The licence parser took a wrapped line starting with "COPYRIGHT HOLDERS" for a copyright notice and rejected such an MIT text; none of the vendored licences changes.
