# desktop-distribution evidence

Generated by scripts/gen.mjs from rules.json and evidence/ledger.json; do not edit by hand. Error rules have a check and fixtures that the check was seen to fail; warn rules guide without blocking. Claims are paraphrased; values are ranges or principles.

## Rules

| Rule | Level | Statement | Evidence |
|---|---|---|---|
| DD-SIGN-01 | error | A Mac app given out as a build passes codesign --verify --deep --strict: its seal is intact and every nested executable, library and bundle is signed, inside out, before the app itself. | IL-20, IL-19 |
| DD-TEAM-01 | error | Every helper, runtime and library inside the app is signed with the app's own team identifier (or, for an ad hoc app, ad hoc too), and no helper starts node, python, ruby, deno or bun from outside the bundle: a peer that checks the team identifier, and library validation under the hardened runtime, refuse code from another team. | IL-19 |
| DD-GATE-01 | error | A Developer ID app distributed outside the App Store is notarized: spctl --assess --type execute accepts it with the source Notarized Developer ID. | IL-20 |
| DD-INSTALL-01 | error | A shell installer downloads over https with certificate checks on, computes the SHA-256 of the archive and compares it with the published checksum, stopping on a mismatch, before it unpacks anything. | IL-20 |
| DD-INSTALL-02 | error | A shell installer verifies the unpacked app with codesign --verify --deep --strict before it moves the app into place, since curl leaves no quarantine flag for Gatekeeper to act on. | IL-20 |
| DD-INSTALL-03 | error | A shell installer copies the app with ditto to a staging path beside the destination and replaces the installed copy with two renames (the old copy aside, the staged copy into place), never by deleting the installed app first or copying over it in place. | IL-20 |
| DD-CASK-01 | error | A Homebrew cask uses the declarative install-step stanzas that the current cask style check wants instead of Ruby preflight, postflight, uninstall_preflight or uninstall_postflight blocks. | IL-22 |
| DD-CASK-02 | error | A cask's uninstall stanza removes no login item and no files under ~/Library, since brew upgrade runs uninstall too; those go in zap. | IL-22 |
| DD-CASK-03 | error | The cask of an app that updates itself declares auto_updates true and bumps version and sha256 for every release, so Homebrew and the app install the same build. | IL-22 |
| DD-FEED-01 | error | A self-update feed carries, from the first release on, an entry with an https url and a signature for every platform the release ships (darwin-aarch64 and darwin-x86_64 by default), and a version; a Sparkle appcast's newest item has an https enclosure with an EdDSA signature and a version. | IL-21 |
| DD-WARN-ADHOC | warn | An ad hoc or development signature is for builds the person installs on their own Mac or through the checksum-checking installer; anyone else downloading the app gets a Developer ID build that is notarized. | IL-20 |
| DD-WARN-RUNTIME | warn | Developer ID code has the hardened runtime and a secure timestamp, which notarization requires. | IL-20 |
| DD-WARN-PATH | warn | Build, sign and package with /usr/bin first on PATH: an xattr, codesign, ditto, hdiutil or plutil installed by pip, Homebrew or npm ahead of the system copy can break bundling or signing. | IL-23 |
| DD-WARN-XATTR | warn | An installer removes the quarantine flag with /usr/bin/xattr by its full path, and only from the copy that passed the checksum and the signature check. | IL-20, IL-23 |

| DD-WARN-DMG | warn | A disk image given out with a Developer ID app is signed, notarized and stapled itself, and checked with hdiutil verify and spctl before it is published. | IL-20 |
| DD-WARN-BETA | warn | On a beta of macOS, expect Homebrew to ask for the newest Xcode or Command Line Tools and to miss bottles; leave App Store apps to macOS automatic updates rather than mas upgrade, which needs sudo. | IL-23 |
