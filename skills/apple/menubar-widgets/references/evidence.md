# menubar-widgets evidence

Generated by scripts/gen.mjs from rules.json and evidence/ledger.json; do not edit by hand. Error rules have a check and fixtures that the check was seen to fail; warn rules guide without blocking. Claims are paraphrased; values are ranges or principles.

## Rules

| Rule | Level | Statement | Evidence |
|---|---|---|---|
| MW-APPEAR-01 | error | A handler that observes effectiveAppearance (KVO, a Combine publisher or observeValue) marks a view for display or replaces its image or title only after comparing the light or dark match with the last one; an observer that redraws on every callback can feed itself through the menu bar snapshot and keep a core busy. | IL-13 |
| MW-CONFIG-01 | error | A widget that should offer options uses AppIntentConfiguration with a WidgetConfigurationIntent whose parameters use AppEntity types, keeping its kind string; StaticConfiguration offers nothing in Edit Widget, so it is wrong wherever the sources declare a configuration intent no AppIntentConfiguration uses, or the task asks for options. | IL-15 |
| MW-STALE-01 | error | After an install or self-update, no process of the app's extensions started before the bundle was installed or runs an executable outside it; the app stops stale extension processes, re-registers the extension with pluginkit -a and reloads all timelines at launch. | IL-14 |
| MW-SNAP-01 | error | Every widget snapshot entry fits its width and height inside its content margins and renders to a PNG of that size times the scale; content that needs more width or height than the widget has is capped or shortened before it ships, and every entry of a non-empty catalog writes its own PNG. | IL-16 |
| MW-SNAP-02 | error | Each widget snapshot PNG is byte-equal to the previous build's, or the difference is looked at and accepted by writing a new baseline. | IL-16 |
| MW-WARN-KIND | warn | Write each widget kind once, as a shared constant that the widget and every reloadTimelines(ofKind:) call use, and never rename it after release: a new kind drops the widgets people placed. | IL-15 |
| MW-WARN-PARAMS | warn | A WidgetConfigurationIntent used by AppIntentConfiguration declares at least one @Parameter; a list of choices is an AppEntity with an EntityQuery. | IL-15 |
| MW-WARN-INTENTS | warn | A build made without Xcode runs the App Intents metadata extraction itself and lists the entity query, transient entity, intents package and dynamic options protocols, or the extracted metadata is incomplete and the options do not show. | IL-15 |
| MW-WARN-BATCH | warn | Render widget snapshots in several processes rather than one long run, since very many renders in one process can abort; the runner renders 40 entries per process by default and refuses more than 60. | IL-16 |
| MW-WARN-TESTCOPY | warn | Test a menu bar or widget app as a debug build with its own bundle identifier and data folder, never by replacing, stopping or re-registering the installed copy; capture its windows from inside the logged-in session. | IL-17 |
| MW-WARN-EXTSIGN | warn | A widget extension is sandboxed and signed with its own entitlements before the host app, whose signature must not replace them; it starts from its WidgetBundle in the system extension entry point, a notarized build carries a secure timestamp, and entitlements are probed from inside an app bundle. | IL-18 |
